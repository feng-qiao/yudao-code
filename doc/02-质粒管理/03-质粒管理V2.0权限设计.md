# 质粒管理 V2.0 权限设计

## 1. 设计目标

本模块权限设计基于 RuoYi-Vue-Pro 现有 RBAC、菜单权限、按钮权限、数据权限、文件权限及审计能力进行扩展。

核心原则：

1. **角色权限负责“能不能做”。**
2. **数据权限负责“能操作哪些数据”。**
3. **字段权限负责“能看到哪些字段”。**
4. **后端接口必须进行最终权限校验，不能只依赖前端隐藏按钮。**
5. **库管员的数据范围必须严格限定在自己负责的质粒类型。**
6. **普通用户不能因为拥有某条质粒的创建权限而获得库存、位置等敏感信息。**
7. **超级管理员拥有全部质粒业务权限。**
8. **质粒类型负责人同时承担该类型的审核职责，不再设计独立审核员角色。**

# 2. 角色定义

## 2.1 普通用户

角色职责：

- 查询公开质粒信息
- 创建自己的质粒登记草稿
- 修改自己的草稿
- 删除自己的草稿
- 提交质粒登记
- 查看自己提交的质粒及审核结果
- 修改被驳回的登记并重新提交
- 发起质粒借用申请
- 查看自己的借用记录
- 查看自己的归还记录
- 发起归还申请
- 导出自己的借用记录

禁止：

- 查看库存数量
- 查看质粒实际体积
- 查看甘油菌规格
- 查看甘油菌数量
- 查看冰箱、层、盒、位置
- 查看其他用户的序列图谱文件
- 修改正式归档质粒
- 删除已提交/审核通过的质粒
- 审核质粒
- 修改库存
- 审核借用
- 审核归还
- 管理违规
- 管理黑名单
- 管理质粒类型
- 修改系统角色及权限

# 3. 库管员

库管员的权限不是全库权限，而是：

> **系统功能权限 + 自己负责质粒类型的数据权限。**

例如：

张三负责“功能质粒库”，那么张三只能管理：

```text
功能质粒库
    ↓
该类型下的质粒
    ↓
该类型下的库存
    ↓
该类型下的借用
    ↓
该类型下的归还
    ↓
该类型下的违规
```

不能管理其他类型。

## 3.1 库管员可以

### 质粒管理

- 查看自己负责类型的完整质粒信息
- 审核质粒登记
- 驳回质粒登记
- 修改自己负责类型的正式质粒信息
- 管理序列图谱
- 管理存储信息
- 管理存放位置

### 库存管理

- 查看库存
- 设置低库存阈值
- 入库
- 出库
- 盘点
- 库存调整
- 查看库存流水
- 查看库存变化前后数量

### 借用管理

- 查看自己负责类型的借用申请
- 审核借用
- 设置实际借用数量
- 设置归还规则
- 设置归还时间
- 设置归还要求
- 批准/拒绝借用

### 归还管理

- 查看自己负责类型的归还申请
- 审核归还
- 确认实际归还数量
- 确认库存入账

### 违规管理

- 查看自己负责类型产生的违规记录
- 警告用户
- 暂停借用权限
- 加入黑名单
- 移除黑名单

### 查询和导出

- 查询自己负责类型的质粒
- 查询自己负责类型的借用记录
- 查询自己负责类型的归还记录
- 查询库存流水
- 导出管理范围内的数据

# 4. 超级管理员

超级管理员拥有整个质粒管理模块的全部权限：

```text
全部质粒类型
全部质粒
全部库存
全部借用
全部归还
全部违规
全部黑名单
全部质粒类型配置
全部库管员配置
```

同时负责：

- 新增质粒类型
- 修改质粒类型
- 启用/停用质粒类型
- 指定质粒类型库管员
- 更换库管员
- 系统权限配置
- 数据权限配置
- 异常业务处理
- 审计及日志查看

# 7. 库存权限

推荐：

```text
lab:plasmid:inventory:query
lab:plasmid:inventory:in
lab:plasmid:inventory:out
lab:plasmid:inventory:stocktake
lab:plasmid:inventory:adjust
lab:plasmid:inventory:flow
lab:plasmid:inventory:threshold
lab:plasmid:inventory:export
```

含义：

| 权限                | 功能           |
| ------------------- | -------------- |
| inventory:query     | 查看库存       |
| inventory:in        | 入库           |
| inventory:out       | 出库           |
| inventory:stocktake | 盘点           |
| inventory:adjust    | 库存调整       |
| inventory:flow      | 查看库存流水   |
| inventory:threshold | 设置低库存阈值 |
| inventory:export    | 导出库存       |

以上八个权限点为 V2 正式库存业务唯一权限命名；禁止使用 `lab:plasmid-inventory:*`、`lab:plasmid-inventory-flow:*` 形式命名。

角色数据范围：

```text
普通用户：库存业务全部禁止
库管员：仅可操作自己负责的质粒类型
超级管理员：全部质粒类型、全部库存业务
```

正式库存业务仅对 audit_status = APPROVED 且未停用的质粒开放；库存业务停用（DISABLED）后禁止一切库存操作。

# 12. 数据权限设计

本模块的数据权限是整个权限系统的核心。

不能只使用：

```text
角色 = 库管员
```

来判断数据。

必须同时判断：

```text
当前用户
+
当前角色
+
质粒类型
+
业务状态
+
数据归属
```

------

# 13. 普通用户数据权限

普通用户的数据权限分成两个范围。

## 13.1 自己的数据

满足：

```text
plasmid.creator = 当前用户ID
```

或者按照实际业务提交人字段判断。

可以查看：

```text
自己的草稿
自己的待审核数据
自己的审核通过数据
自己的审核驳回数据
```

------

## 13.2 公共数据

对于其他用户创建的质粒，只允许：

```text
audit_status = 审核通过
```

然后返回公开字段。

普通用户不能因为拥有：

```text
lab:plasmid:query
```

就获得完整数据。

------

# 14. 库管员数据权限

库管员的数据范围由：

```text
lab_plasmid_type.manager_id
```

决定。

查询质粒时必须加入：

```text
lab_plasmid.plasmid_type_id
    ↓
lab_plasmid_type.id
    ↓
lab_plasmid_type.manager_id = 当前用户ID
```

也就是说：

```text
当前用户 = 类型负责人
```

才能获得该类型的数据权限。

------

# 15. 超级管理员数据权限

超级管理员：

```text
不限制 plasmid_type_id
```

可以访问全部：

```text
质粒
库存
审核
借用
归还
违规
黑名单
```

# 22. 序列图谱文件权限

序列图谱不能简单地把文件 URL 返回给所有用户。

规则：

```text
普通用户查看其他用户质粒 → 不返回 sequenceMap
普通用户查看自己的质粒 → 返回 sequenceMap
库管员 → 返回自己负责类型的 sequenceMap
超级管理员 → 返回全部 sequenceMap
```

测序/检测报告遵循相同规则：

```text
自己的质粒：sequence file / sequencing report → 可以查看
别人的质粒：sequence file / sequencing report → 不可以查看
库管员：负责类型全部可查看
超级管理员：全部可查看
```

文件下载接口同样必须进行权限检查。

不能出现：

```text
拿到 fileId
↓
直接下载文件
```

而绕过质粒权限。

未来的“查看他人测序报告申请”流程**暂不实现**，仅作为未来规划记录。

# 22A. Storage / Inventory / 原始位置 / 正式位置权限

最终数据级权限矩阵：

| 数据             | 本人 | 他人 | 库管员 | 超级管理员 |
| ---------------- | ---: | ---: | -----: | ---------: |
| 基础档案         |  ✅  |  ✅  |    ✅  |        ✅  |
| 本人序列图谱     |  ✅  |  ❌  |    ✅  |        ✅  |
| 本人测序报告     |  ✅  |  ❌  |    ✅  |        ✅  |
| Storage 保存资料 |  ❌  |  ❌  |    ✅  |        ✅  |
| 原始位置         |  ❌  |  ❌  |    ✅  |        ✅  |
| 正式位置         |  ❌  |  ❌  |    ✅  |        ✅  |
| Inventory        |  ❌  |  ❌  |    ✅  |        ✅  |
| Inventory Flow   |  ❌  |  ❌  |    ✅  |        ✅  |

说明：

- “Storage 保存资料”指 volume、glycerin_spec、glycerin_amount、存放位置等敏感字段；storage_form、concentration 对本人可见（见第 18 节）。
- 原始位置（original_*）与正式位置（plasmid_* / glycerin_*）对普通用户（含本人）均不返回。
- **不能只通过前端隐藏字段实现上述权限，最终必须由后端数据返回边界保证。**

Storage 操作权限：

```text
查看 Storage：库管员（负责类型）/ 超级管理员
修改 Storage：库管员（负责类型，审核核查及后续维护）/ 超级管理员
删除 Storage：普通用户 ❌ / 库管员 ❌ / 不提供业务 DELETE
```

Inventory / InventoryFlow 操作权限：

```text
删除 Inventory：普通用户 ❌ / 库管员 ❌ / 不提供业务 DELETE
删除 InventoryFlow：普通用户 ❌ / 库管员 ❌ / 不提供业务 DELETE
```

Storage、Inventory、InventoryFlow 共同构成质粒库存历史链，正式数据不得通过业务 DELETE 删除。

------

# 23. 审核权限

质粒审核必须同时满足：

```text
拥有审核权限
+
属于库管员/超级管理员
+
数据属于自己负责类型
+
当前状态 = 待审核
```

库管员审核时：

```text
当前用户
    ↓
lab_plasmid_type.manager_id
    ↓
plasmid.plasmid_type_id
```

必须匹配。

否则：

```text
禁止审核
```

------

# 24. 借用审核权限

借用审核必须检查：

```text
当前用户拥有 borrow:audit
+
当前用户是该质粒类型负责人
+
借用申请状态 = 待审核
```

审核前还必须检查：

```text
质粒审核状态 = 审核通过
质粒未停用
库存状态允许借用
申请数量 > 0
申请用户未被禁止借用
```

------

# 25. 借用出库权限

借用审批通过以后，系统执行：

```text
借用批准
↓
生成库存出库流水（OUTBOUND，不得使用 BORROW 流水类型）
↓
扣减 current_quantity
↓
记录 before_quantity
↓
记录 after_quantity
```

普通用户不能直接调用库存出库接口。

即使普通用户人为构造：

```text
POST /inventory/out
```

后端也必须拒绝。

------

# 26. 归还权限

普通用户：

```text
只能提交自己的归还申请
```

库管员：


# 38. 本文最终结论

质粒管理 V2.0 的权限体系采用：

```text
RBAC角色权限
        +
业务数据权限
        +
字段级数据隔离
        +
业务状态控制
        +
后端接口校验
```

形成完整权限模型：

```text
普通用户
    ↓
公开数据 + 自己的数据

库管员
    ↓
自己负责的质粒类型

超级管理员
    ↓
全部质粒类型
```

其中最核心的数据权限关系为：

```text
lab_plasmid.plasmid_type_id
                ↓
lab_plasmid_type.id
                ↓
lab_plasmid_type.manager_id
                ↓
当前登录用户
```

因此：

> **“质粒类型 → 唯一库管员 → 该类型全部业务数据”是本模块权限设计的核心链路。**

任何质粒审核、库存、借用、归还、违规等业务，都必须沿着该数据权限链进行校验。

# 39. Task04-B-3A-FIX 库存业务裁决冻结（2026-10-05）

本节为 Task04-B-3A 调查后由项目负责人正式裁决的库存规则，与正文冲突时以本节为准。

## 39.1 适用范围：仅 APPROVED 正式质粒

正式库存业务（INBOUND / OUTBOUND / STOCKTAKE / ADJUSTMENT）只允许对 `audit_status = APPROVED` 的质粒执行。DRAFT / PENDING / REJECTED 一律禁止正式库存增减。B-2 阶段 DRAFT Inventory（current_quantity = 0）属于登记阶段申报/初始化数据，不构成允许日常库存操作的依据。

## 39.2 流水类型

正式业务仅使用三类流水：INBOUND（库存增加，含日常入库与归还审核通过后的增加）、OUTBOUND（库存减少，含日常出库与借用审核通过后的扣减）、ADJUSTMENT（盘点差异与管理性调整）。BORROW / RETURN 保留为历史/兼容字典值，当前 V2.0 正式业务不得使用，代码不得创建 BORROW / RETURN Flow。DISPOSAL 同理保留，V2.0 不实现报废处置业务。

## 39.3 DISABLED

DISABLED 是库存业务停用状态。质粒被业务停用 → Inventory 置 DISABLED，优先级高于 AVAILABLE / LOW / EMPTY，不得再按数量重算。进入 DISABLED 后禁止 INBOUND / OUTBOUND / STOCKTAKE / ADJUSTMENT。V2.0 暂不实现 DISABLED 恢复业务；未来需要时必须通过新的需求变更任务设计。

## 39.4 删除规则

Storage、Inventory、InventoryFlow 共同构成质粒库存历史链，正式数据不得通过业务 DELETE 删除，三者均不提供业务删除能力。历史数据必须保留；停用、失效等需求通过独立业务机制实现。现有 Inventory / Flow 骨架 DELETE 端点于 B-3 编码阶段移除，本冻结任务不改动 Java。

## 39.5 权限点

统一使用 `lab:plasmid:inventory:query / in / out / stocktake / adjust / flow / threshold / export` 八个权限点；禁止使用 `lab:plasmid-inventory:*`、`lab:plasmid-inventory-flow:*` 作为 V2 正式库存业务权限命名。普通用户库存业务全部禁止；库管员仅可操作自己负责的质粒类型；超级管理员可操作全部。

## 39.6 数量规则

INBOUND：quantity > 0，after = before + quantity。OUTBOUND：quantity > 0 且 before >= quantity，after = before - quantity，库存不足必须拒绝，禁止负库存。ADJUSTMENT：以 actual_quantity 为目标值，adjust_quantity = actual_quantity - current_quantity，after = actual_quantity，且 actual_quantity >= 0。quantity 数据库统一保存绝对变更量（不保存负数），增减方向由 flow_type 决定。

## 39.7 盘点与调整

保留 STOCKTAKE 与 ADJUSTMENT 两个业务入口，均产生 flow_type = ADJUSTMENT 的流水；ADJUSTMENT 必须填写 reason。actual_quantity = current_quantity（零差量）时不产生流水、不更新 last_flow_time，可返回“库存无变化”。

## 39.8 事务与并发

Inventory 更新与 InventoryFlow 插入必须处于同一数据库事务：校验质粒/权限/Inventory → 读取 before → 条件更新 Inventory → 校验更新成功 → 计算 inventory_status → 写 InventoryFlow → 更新 last_flow_time → 提交；任一步失败整体回滚。OUTBOUND 必须使用条件更新（`SET current_quantity = current_quantity - quantity WHERE plasmid_id = ? AND current_quantity >= quantity`）并检查 affectedRows == 1，否则按库存不足/并发失败处理且不写流水。INBOUND / ADJUSTMENT 同样必须保证 before / after / current_quantity / Flow 一致。

## 39.9 阈值与低库存通知

阈值由库管员、超级管理员按权限维护；普通用户禁止修改。修改阈值不属于库存数量变化，不产生 InventoryFlow，但修改后必须重新计算 inventory_status。B-3 只实现低库存状态计算，不实现任何通知发送渠道。

## 39.10 B-2 / B-3 边界

B-2：登记阶段 Storage/Inventory 登记行、initial_quantity_confirmed 确认、current_quantity 初始化与期初 INBOUND。B-3：日常 INBOUND / OUTBOUND、STOCKTAKE、ADJUSTMENT、阈值、状态维护、InventoryFlow 查询、并发控制与权限控制。借用/归还的具体业务接口由后续任务实现，B-3 仅保证库存核心 Service 可被后续业务在事务内复用。
