- `el-calendar`（月视图）+ `el-date-picker`（日期/时间选择）
- `ShortcutDateRangePicker`（区间）
- `Table` / `Form` / `Dialog`（承载规则配置）

**建议方案（不引入新依赖，基于 Vue3 + Element Plus 自研）**：

1. **仪器预约日历**：以 `el-calendar` 月视图为骨架，`#date-cell` 插槽自绘每日时段条（30 分钟粒度格子），点击空格拉起预约弹窗（`Dialog` + `Form`）。

3. **开放窗口可视化**：酶标仪"开放窗口"以周视图（周一~周日 × 开放时段）自绘表格，展示"已开放批次的剩余能力"。
4. **冻干批次**：以时间轴（自绘 `div` 时间轴）展示 48 小时批次占用，避免可视化歧义。

以上均为**本设计阶段方案**，具体实现留待 INSTRUMENT-03/04/05。

# 七、风险清单

| 序号 | 风险 | 影响 | 建议 |
| --- | --- | --- | --- |
| K1 | 同模块两种 DO 基类（`TenantBaseDO` vs `BaseDO`）并存 | 租户隔离不一致 | 仪器业务**统一继承 `TenantBaseDO`**，设计文档明确冻结 |
| K2 | `system_role_menu` 无 (role_id,menu_id) 唯一索引 | 菜单授权重复/幂等失控 | 仪器菜单脚本沿用 NOT EXISTS 守卫范式（本任务不写 SQL，留待部署任务） |
| K3 | 仅改角色授权不改租户套餐 | 仪器菜单对用户不可见 | 部署时角色授权 + 套餐 `menu_ids` 必须**同时**处理 |
| K4 | 前端 `el-calendar` 仅有月视图 | 时段粒度可视化难度 | 自绘时段格子；冻干批次用时间轴 |
| K5 | 预约冲突若仅靠前端校验 | 并发重复预约 | **必须**后端事务内 `FOR UPDATE` + 条件约束，前端仅辅助 |
| K6 | 信用账户"允许超过 100" | 若误加数据库 CHECK/上限约束 | 明确**不加最高分约束**，初始化仅一次由业务+锁保证 |
| K7 | `infra_file` 无 `tenant_id` | 附件跨租户可见 | 附件可见性由业务表归属控制，不依赖文件表 |
| K8 | lab 错误码区间未知 | 新增错误码冲突 | 运行时核验 `ErrorCodeConstants` 现有区间后再追加 |
| K9 | 字符集不一致（业务表 vs 框架 dump 表） | 跨表 JOIN 排序规则冲突 | 设计中冻结仪器表字符集，列入待确认 |
| K10 | `system_dept` 易被误当"实验室"复用 | 维修工单路由语义错误 | 明确新建 `lab_instrument_room`，不得复用部门表代替房间 |

# 八、结论

1. **后端框架能力完备**：lab 模块依赖、多租户、权限注解、字典、消息、文件、定时任务、Excel、操作日志、事务/并发（行锁 + 条件更新 + Redis 锁 + 幂等）全部具备，仪器模块无需引入新技术栈或新依赖。
2. **前端控件齐备但缺预约组件**：表单/表格/上传/用户选择/日期区间均有，但**无预约日历与时间段选择业务组件**，需按 3.10 方案基于 Element Plus 自研（本阶段不安装新组件）。
3. **数据库无仪器/房间业务表**：需新建 20 张 `lab_instrument_*` 表；用户/角色/菜单/字典/消息/文件/日志/租户等支撑表全部复用 system/infra 既有表。
4. **可复用范式明确**：OA 会议室预定（预约冲突）、MES 维修工单（状态机）、质粒 V2.0（历史表 + 附件快照 + 并发控制）为本设计的三条主要参照线。
5. **本报告为纯静态证据**，所有实际库状态见第六章"运行时待核验清单"，不得当作已核验事实。
