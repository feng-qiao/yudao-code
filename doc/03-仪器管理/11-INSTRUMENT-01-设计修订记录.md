# 二、C1：取消自动爽约和自动扣分

## 2.1 修订原因

第一期不支持签到、签退、设备硬件检测，也不具备判断"实际使用情况"的任何技术手段。预约开始时间到达、预约时间进入过去，均**不等于设备被实际使用**，因此：

- 不得由系统自动把预约置为爽约；
- 不得因自动爽约而自动扣信用分；
- 不得由系统按结束时间自动判定"已完成"。

违规处理保留，但只能由**授权负责人依据实际证据手工登记**（走信用加扣分接口，原因类型 `VIOLATION`，必填原因与证据）。

## 2.2 逐项变更

| 位置 | 修订前 | 修订后 |
| --- | --- | --- |
| 00 §4.4 状态集 | PENDING / IN_USE / FINISHED / CANCELED / VOIDED / **NO_SHOW** | 第一期 PENDING / FINISHED / CANCELED / VOIDED；IN_USE 标注为未来签到预留，不产生、不自动流转；NO_SHOW 删除 |
| 00 §4.4 转换 | `PENDING→IN_USE（系统到点）`、`IN_USE→FINISHED（系统到点）`、`PENDING→NO_SHOW（系统，触发扣分）` | 三条自动转换全部删除；`PENDING→FINISHED` 改为**授权负责人/管理员凭证据手工登记** |

| 02 §3.13 history.action | CREATE/ADJUST/CANCEL/FINISH/**NO_SHOW**/VOID | 删除 NO_SHOW；FINISH 标注手工登记 |
| 02 §3.10 | reason_type 字典含"爽约" | 字典说明删除爽约自动项；第一期仅人工登记 |
| 03 §十 异常场景 | "到点未开始→系统 Job 置 NO_SHOW 并扣分"、"结束未点完成→Job 自动 FINISHED" | 两条改为：不自动判定/不自动完成，由负责人核实后手工处理 |

- 信用账户、流水、暂停机制不变。

# 三、C2：取消时间限制

## 3.1 冻结后的规则

1. 普通用户在 **预约开始时间之前任意时刻**均可取消本人预约，**没有"提前 N 分钟"条件**。
2. 预约开始后，普通用户不能取消，只能由**授权仪器负责人或管理员**处理（取消/作废/调整，原因必填）。
3. 规则引擎中**删除 `cancel_before_minutes` 字段**，避免诱导配置未经确认的时限。

## 3.2 逐项变更

| 位置 | 修订前 | 修订后 |
| --- | --- | --- |
| 03 §二 规则字段表 | 含 `cancel_before_minutes`（空=不允许用户取消） | **整行删除** |
| 02 §3.19 booking_rule | 含 `cancel_before_minutes int` | **字段删除** |
| 00 §4.4 用户取消行 | `now <= start - allowCancelBefore` | `now < start_time` 即可，无提前量 |
| 03 §8.2 取消 SQL | `NOW() <= start_time - INTERVAL cancel_before_minutes MINUTE` | USER 分支仅判 `NOW() < start_time`；MANAGER/ADMIN 分支无时间限制，原因必填 |
| 04 §5.2 权限矩阵 | "取消本人预约 ✔（开始前可取消窗口内）" | "✔（开始前任时可取消，无提前量）" |
| 07 §2.7 取消接口 | 数据范围"本人（窗口内）" | "本人（开始前任时可取消）/负责人（开始后）" |
| 09 INSTRUMENT-03 验收 | "用户取消受窗口限制" | "用户开始前任时可取消（无提前量）、负责人可开始后调整" |

> 说明：04 §3.5 原"提前取消（超出允许）扣分"行同步删除——不存在取消时限，因此不存在"超时取消扣分"；违规使用仍可由负责人手工登记。

# 四、C3：预约历史和时间占用分离

## 4.1 冻结后的占用口径

| 状态 | 是否占用时段 | 能否与新预约重叠 | 说明 |
| --- | --- | --- | --- |
| PENDING | 占用 | 否 | 有效预约 |
| IN_USE（未来预留） | 占用 | 否 | 第一期不产生 |
| **FINISHED** | **占用（历史实际占用）** | **否** | 已实际使用的完整历史；**不得仅因 FINISHED 就释放其历史区间** |
| CANCELED | 不占用 | 是 | 取消即释放原时段 |
| VOIDED | 不占用 | 是 | 作废即释放原时段 |

冲突查询条件由 `status IN ('PENDING','IN_USE')` 修订为 `status IN ('PENDING','FINISHED')`（IN_USE 未来启用时加入）。可预约性 = **请求时间范围 + 有效占用状态 + 设备状态**三者联合判定。任何情况下**不得物理删除历史预约**来释放时间。

## 4.2 逐项变更

| 位置 | 修订前 | 修订后 |
| --- | --- | --- |
| 00 §4.4 | 占用集 {PENDING, IN_USE}，其余不占用 | 新增"时间占用口径"表；FINISHED 保留占用，仅 CANCELED/VOIDED 释放；禁止物理删除 |
| 02 §3.12 | 占用状态集 {PENDING, IN_USE} | {PENDING, FINISHED}（未来加 IN_USE）+ C3 说明 |
| 02 §4.1 冲突 SQL | `status IN ('PENDING','IN_USE')` | `status IN ('PENDING','FINISHED')` |
| 03 §7.1 占用表/SQL/排除说明 | 排除 CANCELED/VOIDED/NO_SHOW/**FINISHED** | 仅排除 CANCELED/VOIDED；FINISHED 纳入；NO_SHOW 已删 |
| 03 §8.4 / 02 §4.5 | 冻干批次仅查 OPEN/RUNNING | 冻干同步 C3 口径：OPEN/RUNNING/**FINISHED** 占用，仅 CANCELED 释放 |
| 05 §4.3 / §4.11 / 约束 | 批次冲突 `IN ('OPEN','RUNNING')` | `IN ('OPEN','RUNNING','FINISHED')`，并注明 C3 |
| 09 INSTRUMENT-03 | 排除含 FINISHED | 占用集 PENDING/FINISHED，验收同步 |

## 4.3 设计影响说明

FINISHED 预约的时间均在过去，正常面向未来的预约不会与之相交；保留 FINISHED 占用的实际作用：

1. 防止任何**补录/回溯录入**的预约覆盖真实使用历史；
2. 保证统计（使用率、机时）以完整历史为准；
3. 与"不得删除历史释放时间"形成双保险。

# 五、C4：仪器使用资质按设备管理

## 5.1 冻结后的规则

1. 第一期资质 **仅设备级**：`target_type` 固定写入 `DEVICE`，`target_id = device.id`。
2. 用户通过细胞膜色谱平台**某台设备**审核，只获得该台设备资格，**不自动获得**平台内装柱机/色谱仪等其他设备资格。
3. `PLATFORM` 平台级覆盖属于**待确认扩展**：数据库字段保留可扩展，但第一期**不写入 PLATFORM、不提供平台申请入口、不做平台覆盖判定**。
4. 负责人体系不变：`manager.scope=PLATFORM` 的平台负责人仍可管理/审核平台内各设备（管理授权 ≠ 资质覆盖），审核通过后授予的仍是**设备级**资质。

## 5.2 逐项变更

# 八、后续正式裁决记录

## R3：G26 房间多维修负责人规则（2026-10-15 正式裁决）

- **裁决结论：G26 = 方案 A**。同一个实验室允许配置多名有效维修负责人
  （`lab_instrument_manager` 同一 `scope=ROOM_REPAIR`、`target_id=房间` 可存在多条
  `status=ACTIVE` 记录）。本裁决替代原设计文档中 G26 的"待确认"状态。
- 裁决细则：
  1. 不得对同一实验室的维修负责人设置"仅一条 ACTIVE"的限制；
  2. 新增第二名负责人不得自动解除第一名负责人；
  3. 同一用户在同一实验室、同一负责人类型下不允许重复建立相同有效关系；
  4. 解除某名负责人不影响同实验室其他有效负责人；
  5. 变更、解除及历史查询必须保留完整记录；
  6. 权限校验识别全部有效负责人，不得只读取第一条记录；
  7. 不得引入主负责人/协同负责人等级。
- 边界：多名负责人如何接收与处理维修工单**留待 INSTRUMENT-06 确定**；
  当前禁止实现自动轮询、随机分配、默认分配给第一名、自动平均分配、未经确认的抢单规则。
- 同步文档：`06-维修工单与负责人分配设计.md` §4.3/§八/§九、`合并.md` 对应节。
- 实现核验：INSTRUMENT-01 已交付代码（ManagerDO/Mapper/Service/锁/前端）经
