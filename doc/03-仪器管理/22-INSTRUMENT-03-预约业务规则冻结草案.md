## 二、A 类：已冻结规则（预约模块必须遵守）

### A1 预约准入校验顺序（P1-P9，03 §三 冻结）

```text
P1 设备状态      device.status == NORMAL（SCRAPPED 为报废终态，不得按可预约设备处理）
P2 可预约开关    device.bookable == 1
P3 规则已启用    rule.enabled == 1 且 granularity/min_duration 已配置（未配置=不可预约，F15）
P4 用户资质      本人持有该设备 ACTIVE 资质（第一期仅设备级，C4）
P5 用户暂停      无生效 SINGLE(本设备) / ALL 暂停（判定语义见 A4）
P6 开放范围      bookable_days_before/ahead、open_days、open_time、（酶标仪）开放窗口
P7 时间参数      粒度对齐、[min,max] 时长、end > start
P8 时间冲突      reservation / maintenance / freeze_batch 三方无重叠
P9 落库          事务内锁 + 插入 + history(CREATE)
```

先权限（P1-P5）后时间（P6-P9）；每步失败返回**明确原因码**（23 号文档错误码分配）。

### A2 冲突与占用口径（F5 + C3 冻结）

- 冲突表达式：`existing.start_time < reqEnd AND existing.end_time > reqStart`（左闭右开，相邻不冲突）；
- 占用状态集：预约 `PENDING`（+未来 `IN_USE` 预留）、`FINISHED`（已实际使用历史，**不得被新预约重叠**）；维护 `ACTIVE`；批次 `OPEN/RUNNING/FINISHED`；
- 仅 `CANCELED / VOIDED` 释放时段；**禁止物理删除历史记录释放时间**；
- 冲突必须查库，不得仅内存判断；返回冲突摘要（占用类型、时段、单号）。

### A3 取消 / 调整 / 作废（C2 + 00 §4.4 冻结）

| 行为 | 谁 | 条件 | 失败 |
| --- | --- | --- | --- |
| 取消本人预约 | 用户本人 | **开始前任一时刻可取消，无提前量**（C2，禁止"提前 N 分钟"条件） | 条件更新 affectedRows=0 → 明确报错 |
| 取消/调整他人预约 | 授权负责人（canManageDevice）/管理员 | 开始后亦可，**原因必填**，写 history | 越权拒绝 |
| 作废 VOIDED | 管理 | 原因必填 | 越权拒绝 |
| 手工登记完成 FINISHED | 授权负责人/管理员 | 有实际使用证据；**不按 end_time 自动完成**（C1） | — |

并发保护：条件更新 `WHERE status='PENDING'` + affectedRows 校验（00 §8.2/8.3 冻结方案）。

### A4 暂停拦截语义（H1/H2/G13 裁决冻结，INSTRUMENT-03 必须继承）

1. 创建预约前必须在**服务端**校验生效暂停（P5），不得仅前端提示；
2. 生效暂停判定 = `status='ACTIVE' AND start_time <= now` 且（`scope_type='ALL'` 或 `SINGLE AND device_id=目标设备`）；**不得使用 `end_time > now`**——暂停超过计划结束时间在人工解除前仍按有效暂停处理（H1）；
3. ALL 拦截该用户所有适用设备；SINGLE 仅拦截对应设备；
4. 暂停期间资质审核仍可通过（G13）；**不得**因存在暂停记录把新审批资质判 REJECTED；
5. 不得注册暂停自动解除 Job；
6. 预约侧暂停拦截唯一依据 = `lab_instrument_suspend` 覆盖判定（`selectActiveCovering` 语义），**不得**以 `qualification.status='SUSPENDED'` 替代（G12 仅是登记时点展示联动，见 B5）；
7. 暂停人工解除后按既有规则重新判定，不得缓存"已拦截"结论。

### A8 并发与事务（F6 冻结 + B1 方案 A 已裁决 2026-10-15）

1. 同一设备并发预约由**设备行锁**串行化（03 §8.1 冻结）；
2. 预约创建与暂停创建的竞态由**方案 A（共用 `suspendKey` 用户级 Redisson 锁）**消除——**B1 已由负责人正式批准（2026-10-15），本项自本版本起为冻结基线**；实施细则见 23 号文档 §七；
3. 防连点：`@Idempotent`；
4. **锁顺序固定为 `suspendKey → 设备行锁`**；预约创建、预约调整等路径**不得反向获取锁**；
5. **并发控制必须覆盖关键数据库事务直至提交完成**：`Redis 10 秒固定租约`与`监控埋点/告警`**本身不构成安全性证明**（B1-4）；
6. 若锁可能在事务提交前失效（固定租约 10s 到期），必须**识别并给出经修复或经验证的方案**；在获得可靠证据前，相关**并发验收项标记 HOLD**（B1-5，不得宣称已通过）；
7. 锁内禁止慢操作、外部调用与长批量查询（开发硬性约束，23 号文档 §7.2）；
8. 冻干批次（05）创建必须同样共用 `suspendKey` 锁（05 实施前置约束）；
9. **不得以实现方案 A 为由修改 INSTRUMENT-02 已冻结的资质、信用、暂停业务语义**（B1-6）。
