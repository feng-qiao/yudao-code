## 一、总原则与执行边界

1. **裁决前提（已满足）**：B1~B11 已于 2026-10-15 由负责人正式裁决（22 号第五章）。B1（方案 A）为 03-C 的**阻断级前置**且**已批准**；但按 B1-③④⑤，**"并发互斥覆盖事务提交"在方案 A+ 落地并取得可测证据前，03-C 相关并发验收标记 HOLD**（见 §三 03-C 与 23 §7.4）。B10 的特殊设备参数仍由负责人**逐设备确认后录入**，代码不预设。
2. **SQL 生成与执行分离**：所有 SQL（DDL/DML/菜单授权）均为**设计稿**，由负责人审查后另行授权执行；任何批次不得以"设计完成"视为执行授权。
3. **数据保护**：不修改/删除既有测试数据（设备 id=1/2、manager 3 行）；验收用新测试数据通过 DML 设计稿插入，由负责人执行。
4. **批次推进流程**：沿用既定流程——**前端验收 → 关闭当前批次任务 → 下一批次只读调查 → 开发**；每批可独立验收、独立关闭。
5. **每批交付后编译 + 单测通过**为本批关闭条件；跨批次回归不重复展开。
6. 锁规范（23 §7.2/§7.4）自 03-C 起作为硬性 Code Review 项：锁内操作白名单、锁顺序 `suspendKey → 设备行锁` 单向、锁须覆盖事务提交（方案 A+ watchdog 续期）、10s 租约监控埋点。
