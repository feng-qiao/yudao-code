## 场景 16：普通用户如何上报故障

### 谁可以做？
所有已登录用户（普通用户 / 管理员 / 维修负责人均可上报）。

### 操作路径

```
仪器管理 → 故障上报 → [上报新故障]
```

### 步骤说明

1. 登录系统，进入【仪器管理】模块
2. 点击【故障上报】菜单，进入上报页面
3. 点击【上报新故障】按钮，弹出表单
4. 填写表单：

| 字段 | 是否必填 | 填写建议 |
|------|----------|----------|
| 选择设备 | ✅ | 下拉列表自动展示你有权限使用的已上架仪器 |
| 故障标题 | ✅ | 一句话概括问题，如"冻干机 A 不能启动" |
| 故障描述 | ✅ | 详细描述故障现象、出现时间、你做过什么尝试 |
| 严重程度 | ✅ | MINOR（轻微，不影响使用）/ MAJOR（主要影响）/ CRITICAL（严重，立即停用）|
| 附件 | ⭕ | 可上传故障照片或截图（≤5 张，单张≤10MB） |

5. 点击【提交】
6. 系统生成 **故障单号 FRxxxxxxxx**，跳转到【我的故障列表】
7. 你可以看到故障状态为"已提交"，等待管理员确认

### 我提交后还能做什么？

- 去【我的故障列表】查看状态变化
- 如果管理员驳回（状态变为"已驳回"），可以修改后点击【重新提交】
- 如果管理员长时间未处理，可联系仪器管理员催办
- 如果故障已自行解决，可以手动【取消】（仅限"已提交"状态）

### 示例场景

> 小王正在使用冻干机做实验，发现压缩机异响。他登录系统 → 故障上报 → 选择"冻干机-01" → 标题"冻干机-01 压缩机异响" → 描述"今天下午 3 点开始出现，伴有轻微震动" → 严重程度选 MAJOR → 上传两张照片 → 提交 → 获得故障单号 FR20261020000123。

## 场景 17：管理员如何确认故障 + 创建维修工单

### 谁可以做？
ROOM_ADMIN（仪器管理员）、LAB_ADMIN（实验室管理员）。

### 操作路径

```
仪器管理 → 故障管理 → 故障列表 → [确认并创建工单]
仪器管理 → 维修管理 → 工单列表 → 工单详情 → 【确认】
```

### 步骤说明

1. 登录管理员账号，进入【仪器管理 → 故障管理 → 故障列表】
2. 查看待处理故障（状态"已提交"）
3. 点击某条故障的【确认并创建工单】按钮
4. 系统自动弹出工单创建表单，自动预填设备、故障信息
5. 补充：维修优先级（高/中/低）、期望完成时间
6. 点击【提交】→ 系统生成 **维修工单 ROxxxxxxxx**
7. 工单状态变为"已确认"

### 如果故障无效怎么办？

- 点击【驳回】→ 填写驳回原因（如"重复上报 / 用户误操作自行恢复"）
- 故障状态变为"已驳回"，提交人会收到通知（系统消息）
- 提交人可修改后重新提交

### CRITICAL 严重程度的自动处理

当管理员确认的故障严重程度为 **CRITICAL** 时：
- 系统自动将该设备状态切为"故障"
- 自动扫描该设备所有未来 PENDING 预约并标记"受影响"
- 阻断新的预约创建（需要先恢复设备或人工处理）

## 场景 18：管理员如何指派维修负责人

### 谁可以做？
ROOM_ADMIN（仪器管理员）、LAB_ADMIN（实验室管理员）。

### 操作路径

```
仪器管理 → 维修管理 → 工单列表 → 找到"已确认"状态工单 → 【指派】
```

### 步骤说明

1. 进入【维修管理 → 工单列表】
2. 使用状态筛选项筛选"已确认"工单
3. 点击某条工单的【指派】按钮
4. 弹出指派表单：

| 字段 | 填写说明 |
|------|----------|
| 维修负责人 | 下拉列表，自动展示**所有已分配 ROOM_REPAIR 角色且状态为 ACTIVE 的账号** |
| 期望完成时间 | 设置一个合理的完成截止日期 |
| 备注 | 可选，如"先排查传感器线路" |

5. 点击【确认指派】
6. 工单状态变为 **"已指派"**，维修负责人收到系统通知
7. 维修负责人登录后在【我的维修任务】中可见此工单

### 常见问题

**Q：下拉列表里没有人？**
A：说明系统中尚未分配任何真实账号到 ROOM_REPAIR 角色，管理员需先在【权限管理 → 业务角色】中添加维修负责人。

## 场景 19：维修负责人如何开始维修 + 记录过程 + 提交维修完成

### 谁可以做？
只有被指派到该工单的维修负责人（`repair_order.assignee_id == currentUserId`）。

### 操作路径

```
仪器管理 → 维修管理 → 我的维修任务 → 找到"已指派"工单 → 【开始维修】
```

### 完整流程

#### 步骤 A：开始维修

1. 进入【我的维修任务】，筛选"已指派"状态
2. 点击工单的【开始维修】按钮
3. 工单状态变为 **"维修中"**
4. 系统自动将设备状态切为"维护中"（MAJOR）或"故障"（CRITICAL），并扫描 PENDING 预约
5. 此时设备在预约端被标记为不可预约

#### 步骤 B：添加维修记录

1. 在工单详情页，点击【添加维修记录】
2. 填写记录类型（诊断 / 维修步骤 / 更换零件 / 备注）+ 内容
3. 可附带照片
4. 保存 → 记录自动追加到维修历史时间线

**建议记录**：
- 故障初步诊断结论
- 具体做了什么（如"拆下后盖检查 → 发现风扇异响 → 更换风扇"）
- 更换的零件名称、型号、数量
- 测试数据、照片

#### 步骤 C：提交维修完成

1. 维修完成后，在工单详情页点击【提交维修完成】
2. 系统要求至少有 **1 条维修历史记录**，否则会提示"请先添加维修记录"
3. 填写：最终维修结论、设备当前状态、费用（可选）
4. 提交 → 工单状态变为 **"已完成，待验收"**
5. 设备状态保持"维护中"，等待管理员验收决定是否恢复

### 可以反复修改吗？

- 在"维修中"状态下，可以随时添加/编辑维修记录
- 提交维修完成后，如果管理员退回（状态变为"退回，重新维修"），可再次点击【开始维修】继续处理

## 场景 20：管理员如何恢复验收（通过 / 退回）

### 谁可以做？
ROOM_ADMIN（仪器管理员）、LAB_ADMIN（实验室管理员）。

### 操作路径

```
仪器管理 → 维修管理 → 工单列表 → 找到"已完成，待验收"工单 → 【验收】
或 工单详情 → 【验收】
```

### 验收通过

1. 查看工单详情：维修历史、更换零件、测试数据、照片
2. 如有需要，现场检查设备
3. 回到工单，点击【验收通过】
4. 填写验收意见（如"确认正常，可恢复使用"）
5. 提交 → 系统在**同一事务**中自动完成 4 件事：
   - ✅ 工单状态 → **已恢复（终态）**
   - ✅ 设备状态 → **正常（NORMAL）**
   - ✅ 写入设备状态历史
   - ✅ 关闭所有关联的预约影响记录（恢复自动阻断）
6. 设备重新出现在预约列表中，允许新的预约

### 验收退回（需继续维修）

1. 如果维修不彻底或需要进一步处理，点击【验收退回】
2. 必须填写退回原因（如"仅更换风扇，但压缩机异常未排查"）
3. 工单状态变为 **"退回，重新维修"**
4. 维修负责人收到通知，进入【我的维修任务】继续处理

## 场景 21：设备故障后已有预约怎么办

### 自动发生的事

当设备因维修进入"维护中"或"故障"状态时，系统**自动扫描该设备所有未来 PENDING 预约**，并在【预约影响管理】中标记：

- 每个受影响的预约被记录到 `instrument_reservation_impact` 表
- 记录影响原因、关联维修工单
- 预约本身不自动取消，由管理员决定

### 管理员可以做什么

进入【仪器管理 → 预约管理 → 预约影响】，查看所有被维修影响的预约：

| 处理方式 | 效果 | 适用场景 |
|----------|------|----------|
| 手动取消该预约 | 预约状态变"已取消"，通知预约人 | 维修周期长，预约人无法等待 |
| 标记忽略 | 预约不变，仅标记"维修不影响" | 小故障不影响该时段预约使用 |
| 改期 | 管理员调整预约时间到设备恢复后 | 双方同意改到稍后 |
| 等待自动恢复 | 管理员验收通过后，系统自动关闭所有影响记录 | 短故障快速修复 |

### 预约人会收到通知吗？

- 管理员手动取消 / 改期时，预约人会收到系统通知
- 自动标记受影响时，预约人暂时**不会收到自动通知**（避免误报警），管理员可通过系统消息手动告知

## 常见报错与处理方法

### 1. 提交故障时报"设备不存在 / 已下架"

**原因**：下拉列表只展示已上架设备，或你对该设备无使用权限。
**解决**：确认设备名称拼写、联系管理员申请设备权限。

### 2. 开始维修时报"不是你被指派的工单"（403）

**原因**：后端校验 `assignee_id != currentUserId`。可能管理员误指派给了别人。
**解决**：联系管理员重新指派。

### 3. 提交维修完成时报"请先添加维修记录"

**原因**：`RepairOrderService` 强制校验至少一条 history 记录。
**解决**：在工单详情页添加至少一条维修步骤/诊断记录后再提交。

### 4. 验收时报"工单状态已变更"

**原因**：并发下别人已经验收过，或你刷新时状态已变。
**解决**：刷新页面后重新进入工单详情查看当前状态。

### 5. 维修负责人登录后"我的维修任务"为空

**可能原因 1**：尚未分配 ROOM_REPAIR 业务关系（P4 阻断项）
**解决**：联系管理员在【业务权限】中分配 `ROOM_REPAIR / ACTIVE`

**可能原因 2**：被指派的工单状态不是 ASSIGNED / IN_PROGRESS / REOPENED
**解决**：检查工单实际状态，或筛选条件调整

### 6. 普通用户看不到【故障上报】入口

**可能原因**：59 号菜单 SQL 未部署，或 Redis 缓存未刷新。
**解决**：管理员检查部署状态（参照 63 号 Checklist）。

### 7. 报错 "Table 'xxx.instrument_fault_report' doesn't exist"

**原因**：58 号 DDL 未执行（最高优先级阻断项）。
**解决**：运维立即执行 58 号 SQL 并重启应用。

## 工单状态全流程速查

```
提交人 ──SUBMITTED──▶
管理员确认 ──CONFIRMED──▶
管理员指派 ──ASSIGNED──▶
维修负责人开始 ──IN_PROGRESS──▶
维修负责人提交完成 ──REPAIRED──▶
管理员验收通过 ──RESTORED（终态）
管理员验收退回 ──REOPENED──▶ 维修负责人继续（回到 IN_PROGRESS）

异常分支:
SUBMITTED ──管理员驳回──▶ REJECTED ──重新提交──▶ SUBMITTED
SUBMITTED ──取消──▶ CANCELED（终态）
```

## R4 最新安全边界补充（2026-10-20）

预约只记录预约时段及管理过程，不代表用户实际使用设备。系统无签到、签退、开始使用或硬件控制能力；故障设备的现场物理停用、警示标识和使用安全由实验室线下流程保障。设备恢复只表示维修验收恢复设备状态，不会自动处理受影响预约；管理员仍须查看影响清单并人工记录后续安排。预约状态、取消、调整、完成和作废继续遵循 INSTRUMENT-03 原规则。
