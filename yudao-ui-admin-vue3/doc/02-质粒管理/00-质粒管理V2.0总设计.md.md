# 一、设计目标

质粒管理 V2.0 不再将“质粒管理”简单理解为一个基础 CRUD 页面，而是按照完整业务生命周期重新设计。

核心业务生命周期：

```text
质粒类型管理
    ↓
质粒登记
    ↓
保存草稿
    ↓
提交审核
    ↓
类型库管员审核
    ↓
审核通过
    ↓
正式归档
    ↓
库存管理
    ↓
借用申请
    ↓
借用审核
    ↓
库存出库
    ↓
使用
    ↓
归还申请
    ↓
归还审核
    ↓
库存回库
    ↓
逾期/违规处理
    ↓
审计记录
```

系统必须区分：

1. 质粒基础档案
2. 质粒类型
3. 审核状态
4. 库存状态
5. 库存流水
6. 借用业务
7. 归还业务
8. 违规处理
9. 黑名单
10. 操作审计

不得将上述不同业务概念混合到单一表或单一状态字段中。

------

# 二、角色设计

系统涉及三个业务角色。

## 2.1 普通用户

普通用户可以：

- 查询公开质粒信息
- 新建自己的质粒登记草稿
- 保存自己的质粒草稿
- 编辑自己的草稿
- 删除自己的草稿
- 提交质粒登记审核
- 查看自己的质粒登记信息
- 提交质粒借用申请
- 查看自己的借用记录
- 提交归还申请
- 查看自己的归还记录
- 导出自己的借用记录
- 查看自己的个人信息

普通用户不能：

- 审核质粒
- 修改其他用户的质粒
- 删除其他用户的质粒
- 管理质粒库存
- 查看敏感库存数量
- 查看质粒存放位置
- 查看甘油菌规格及数量
- 管理质粒类型
- 管理其他用户
- 管理系统角色和权限
- 处理违规
- 管理黑名单

------

## 2.2 库管员

库管员拥有普通用户的全部能力。

同时，库管员针对自己负责的质粒类型拥有管理权限。

每一个质粒类型：

> 只能配置一个库管员。

库管员同时承担该类型的审核职责。

库管员可以：

- 查看自己负责类型的完整质粒信息
- 审核质粒登记
- 驳回质粒登记
- 修改自己负责类型的质粒信息
- 管理自己负责类型的库存
- 入库
- 出库
- 库存盘点
- 库存调整
- 审核借用申请
- 确定实际借用数量
- 设置归还规则
- 设置归还时间
- 审核归还
- 处理逾期
- 创建违规记录
- 处理违规
- 设置黑名单
- 移除黑名单
- 设置低库存阈值
- 查看自己负责类型的借用统计
- 导出自己负责类型的业务记录

库管员不能：

- 管理其他类型
- 审核其他类型质粒
- 修改其他类型质粒
- 管理系统角色
- 修改系统权限
- 修改其他库管员的职责范围

------

## 2.3 超级管理员

超级管理员拥有全部质粒管理权限。

可以：

- 查看所有质粒
- 管理所有质粒类型
- 新增质粒类型
- 修改质粒类型
- 启用/停用质粒类型
- 为每个类型指定唯一库管员
- 查看全部库存
- 管理全部库存
- 查看全部借用
- 查看全部归还
- 处理全部违规
- 管理全部黑名单
- 查看全部审核记录
- 查看全部业务审计记录
- 管理系统角色
- 管理系统权限
- 管理系统配置

------

# 三、质粒类型设计

系统初始提供以下六种质粒类型：

1. 构建GPCR稳转株非嗅觉质粒库
2. 构建GPCR稳转株嗅觉质粒库
3. 构建非GPCR稳转株质粒库
4. 功能质粒库
5. 结构质粒库
6. 其他

质粒类型必须独立建表。

建议表：

```text
lab_plasmid_type
```

每个类型具有：

- 类型名称
- 类型编码
- 类型状态
- 库管员
- 创建信息
- 修改信息

其中：

```text
一个质粒类型
    ↓
最多且只能有一个有效库管员
```

数据库层面需要建立唯一性约束/业务校验，防止一个类型出现多个有效库管员。

# 五、菜单功能说明

## 5.1 质粒查询

用于查询系统中的公开质粒信息。

普通用户可以使用。

普通用户可以看到：

- 质粒编号
- 序号
- 质粒名称
- 受体
- 种类
- 抗性
- 载体名称
- 荧光标签
- 突变
- 改造
- 标签
- 质粒类型
- 创建者

普通用户不能看到：

- 质粒库存量
- 甘油菌规格
- 甘油菌数量
- 质粒存放位置
- 甘油菌存放位置
- 其他敏感库存信息

------

## 5.2 我的质粒

显示当前登录用户自己创建/登记的质粒。

用户可以：

- 新建
- 保存草稿
- 编辑草稿
- 删除草稿
- 提交审核
- 查看审核结果

审核通过后的正式记录不能由普通用户随意修改或删除。

------

## 5.3 质粒审核

仅：

- 库管员
- 超级管理员

可以进入。

库管员只能看到自己负责类型的待审核记录。

超级管理员可以看到全部类型。

审核操作：

```text
待审核
   ├── 审核通过
   │      ↓
   │    正式归档
   │
   └── 审核驳回
          ↓
       用户修改
          ↓
       再次提交
```

审核必须记录：

- 提交人
- 提交时间
- 审核人
- 审核时间
- 审核结果
- 审核意见

# 六、质粒登记业务流程

## 6.1 新建

普通用户进入：

```text
我的质粒 → 新建
```

系统创建草稿。

状态：

```text
audit_status = 草稿
```

------

## 6.2 编辑草稿

草稿状态下，创建者可以编辑。

可以修改：

- 质粒编号
- 质粒名称
- 受体
- 种类
- 抗性
- 载体名称
- 荧光标签
- 突变
- 改造
- 标签
- 质粒类型
- 序列图谱
- 保存形式
- 浓度
- 测序/检测报告

------

## 6.3 提交审核

用户提交后：

```text
草稿
 ↓
待审核
```

提交后，普通用户不能继续修改正式审核中的字段。

系统记录：

- 提交人
- 提交时间
- 提交时数据快照/变更信息

------

## 6.4 审核通过

库管员审核通过：

```text
待审核
 ↓
审核通过
 ↓
正式归档
```

审核通过后：

- 质粒成为正式档案
- 根据质粒类型进入对应管理范围
- 可以进入库存管理流程

------

## 6.5 审核驳回

审核不通过：

```text
待审核
 ↓
审核驳回
```

必须填写：

```text
审核意见
```

用户可以：

```text
审核驳回
 ↓
用户修改
 ↓
重新提交
 ↓
待审核
```


# 十四、库存设计原则

质粒库存不能继续直接依赖：

```text
lab_plasmid.volume
```

作为动态库存账本。

V2.0采用：

```text
库存主表
+
库存流水表
```

------

# 十五、库存主表

建议：

```text
lab_plasmid_inventory
```

职责：

> 保存当前库存状态。

至少需要支持：

- 质粒ID
- 当前库存
- 低库存阈值
- 库存状态
- 最后库存更新时间
- 创建/修改信息

库存单位统一：

```text
μL
```

------

# 十六、库存流水表

建议：

```text
lab_plasmid_inventory_flow
```

每次库存变化必须产生流水。

库存操作包括：

```text
入库
出库
借用
归还
盘点调整
报废/处置
```

每条流水至少记录：

- 质粒
- 操作类型
- 操作数量
- 操作前库存
- 操作后库存
- 操作人
- 操作时间
- 业务关联单据
- 原因
- 备注

------

# 十七、库存计算原则

库存变化必须通过库存业务产生。

例如：

```text
期初库存：1000 μL

入库：+500 μL
借用：-200 μL
归还：+100 μL
盘点调整：-50 μL

最终库存：

1000 + 500 - 200 + 100 - 50
= 1350 μL
```

不允许前端直接修改当前库存数字。

库存调整必须形成库存流水。

------

# 十八、低库存预警

库管员可以为质粒设置低库存阈值。

例如：

```text
当前库存 > 100 μL
    ↓
正常

当前库存 <= 100 μL
    ↓
低库存

当前库存 = 0
    ↓
耗尽
```

系统根据库存变化自动计算库存状态。

达到低库存阈值时通知对应库管员。

------

# 十九、借用业务

普通用户可以提交借用申请。

借用申请至少包含：

- 借用质粒
- 申请数量
- 借用原因
- 申请人
- 申请时间

------

# 二十、借用流程

```text
用户提交借用
      ↓
待审核
      ↓
类型库管员审核
      ↓
检查库存
      ↓
检查借用合理性
      ↓
确定实际借用数量
      ↓
审核通过
      ↓
库存出库
```

审核拒绝：

```text
待审核
 ↓
拒绝
 ↓
结束
```

拒绝不改变库存。

------

# 二十一、实际借用数量

用户申请数量与实际批准数量必须分开。

例如：

```text
申请数量：500 μL

库管员批准：
实际借用：300 μL
```

数据库必须保存：

```text
requested_quantity
approved_quantity
```

不能直接覆盖申请数量。

------

# 二十二、归还规则

归还规则必须由库管员在借用审核过程中确定。

支持五种类型：

### 1. 质粒+甘油菌

需要归还质粒和甘油菌。

### 2. 只归还质粒

只需要归还质粒。

### 3. 只归还甘油菌

只需要归还甘油菌。

### 4. 无须归还

该借用不需要归还。

### 5. 其他

选择“其他”时：

> 必须填写自定义归还类型/原因。

------

# 二十三、归还信息

需要归还时，库管员确定：

- 归还时间
- 归还数量
- 归还类型
- 归还要求
- 备注

系统根据归还规则生成相应的归还业务。

------

# 二十四、逾期管理

归还时间到达后：

```text
到期
 ↓
系统提醒
 ↓
仍未归还
 ↓
逾期
 ↓
违规记录
 ↓
库管员处理
```

库管员可以根据实际情况：

- 警告
- 暂停相关借用权限
- 加入黑名单

黑名单支持解除。

------

# 二十五、违规管理

违规记录独立业务对象。

建议：

```text
lab_plasmid_violation
```

用于记录：

- 用户
- 借用记录
- 违规类型
- 违规时间
- 违规说明
- 处理结果
- 处理人
- 处理时间
- 备注

------

# 二十六、黑名单

建议：

```text
lab_plasmid_blacklist
```

黑名单独立管理。

至少记录：

- 用户
- 加入原因
- 加入时间
- 操作人
- 当前状态
- 移除时间

- 移除原因

黑名单不是简单的用户字段。

------

# 二十七、业务审计

质粒管理需要保留重要操作审计。

至少包括：

```text
创建
保存草稿
编辑草稿
提交审核
审核
驳回
删除草稿
库存入库
库存出库
库存盘点
库存调整
借用申请
借用审核
归还申请
归还审核

黑名单移除
```

审计信息至少包括：

- 操作人
- 操作时间
- 操作类型

- 对象ID
- 操作前数据
- 操作后数据
- 操作结果

如果业务审计需要保存业务快照，则单独建立业务审计设计，不重复实现框架已有普通操作日志。

# 二十八、核心数据库实体

# 三十、现有 lab_plasmid 的处理原则

当前系统已经存在：

```text

```

并且已经完成基础 CRUD。

V2.0不建议立即删除。

原因：

1. 当前CRUD已经跑通
2. 后续需要迁移旧数据
3. 删除会增加不可控风险
4. 数据库设计确认前不应该破坏已有功能

因此：

> 先保留，冻结旧版本逻辑，再进行 V2.0 重构。

# 三十七、数据库设计原则

V2.0数据库遵循：

### 原则1：业务对象独立

不同生命周期的数据不能全部塞进 `lab_plasmid`。

### 原则2：历史记录独立

审核、库存流水、借用、归还等需要保留历史。

### 原则3：状态分离

审核状态与库存状态必须分离。

### 原则4：敏感数据权限控制

不能因为数据存在数据库，就默认所有角色可见。

### 原则5：库存账实分离

库存当前值与库存变化历史分离。

### 原则6：框架字段复用

RuoYi-Vue-Pro已有：

- creator
- create_time
- updater
- update_time
- deleted
- tenant_id

等能力，应优先复用。

### 原则7：避免重复字段

在增加 `creator_id`、`creator_name` 等业务字段之前，应确认是否与框架审计字段职责重复。

# 四十二、当前版本冻结规则

在正式进入数据库设计之前，以下规则视为V2.0已确认规则：

- 使用反馈：删除
- 质粒类型备注：删除
- 独立审核员：删除
- 一个类型多个库管员：禁止
- 一个类型一个库管员：确定
- 库管员同时承担审核职责：确定
- 浓度单位：ng/μL
- 库存单位：μL
- 序列图谱：必填；无文件时必须说明原因
- 测序/检测报告：保留，但非必填
- 审核状态与库存状态：分离
- 普通用户不可查看库存敏感数据
- 普通用户不可查看存放位置
- 库管员只能管理自己负责类型
- 超级管理员管理全部类型
- 库存采用独立库存表 + 库存流水表
- 借用申请数量与实际批准数量分离
- 归还规则固定为五种
- “其他”归还类型必须填写自定义内容
- 逾期进入违规处理
- 黑名单支持加入和解除
- 重要操作需要审计
- 不立即删除旧表
- 不继续扩展旧 `lab_plasmid_ext` 作为V2.0核心设计
- 不允许AI自行改变以上规则
