# 质粒管理 V2.0 需求设计

> 版本：V2.0
> 状态：设计阶段
> 上游文档：00-质粒管理V2.0总设计.md
> 下游文档：02-数据库设计、03-权限设计、04-接口设计

------

# 一、需求概述

质粒管理 V2.0 用于管理实验室质粒从：

```text
质粒类型
→ 质粒登记
→ 审核
→ 正式归档
→ 库存
→ 借用
→ 归还
→ 逾期
→ 违规
→ 黑名单
→ 审计
```

的完整业务生命周期。

系统不再以简单 CRUD 为核心，而采用“档案 + 审核 + 库存 + 借用 + 归还 + 违规”的业务模式。

------

# 二、系统角色

系统涉及三个角色：

1. 普通用户
2. 库管员
3. 超级管理员

------

# 三、普通用户需求

## 3.1 质粒查询

普通用户可以查询系统公开质粒信息。

支持：

- 质粒编号查询
- 质粒名称查询
- 种类查询
- 抗性查询
- 载体名称查询
- 荧光标签查询
- 质粒类型查询
- 创建者查询

查询结果可以查看公开字段。

------

## 3.2 新建质粒

普通用户可以创建自己的质粒登记。

新建后默认为：

```text
草稿
```

草稿状态可以：

- 编辑
- 保存
- 删除
- 提交审核

------

## 3.3 我的质粒

普通用户可以查看自己创建的质粒。

可以看到：

- 基础信息
- 序列图谱
- 保存形式
- 浓度
- 审核状态
- 审核意见

不能看到敏感库存信息。

------

## 3.4 草稿编辑

只有创建者本人可以编辑自己的草稿。

正式提交审核后：

```text
待审核
```

原则上不能继续修改审核中的核心信息。

------

## 3.5 删除草稿

普通用户只能删除自己的草稿。

已经：

- 提交审核
- 审核通过

的正式业务数据不能通过普通用户的删除操作直接删除。

------

```text

```

后续采用系统字典进行维护。

荧光标签支持多选。

```text
GFP
```

# 八、质粒类型

初始支持六种：

1. 构建GPCR稳转株非嗅觉质粒库
2. 构建GPCR稳转株嗅觉质粒库
3. 构建非GPCR稳转株质粒库
4. 功能质粒库
5. 结构质粒库
6. 其他

质粒类型由超级管理员维护。

------

# 九、序列图谱

序列图谱属于质粒登记的重要资料。

要求：

- 必填
- 支持文件上传
- 保存文件ID
- 保存文件名称
- 保存上传人
- 保存上传时间

如果没有序列图谱：

> 必须填写没有文件的原因。

------

# 十、保存信息

## 10.1 保存形式

支持多选：

```text
甘油菌
冻干
质粒DNA
```

------

## 10.2 浓度

必须填写。

单位：

```text
ng/μL
```

必须进行数值校验。

------

## 10.3 测序/检测报告

测序/检测报告：

> 可选。

如果有报告，可以上传。

没有报告不要求填写原因。

------

# 十一、敏感信息

以下属于业务数据，但属于受限数据：

- 质粒体积
- 甘油菌规格
- 甘油菌量
- 质粒冰箱/层
- 质粒盒
- 质粒位置
- 甘油菌冰箱/层
- 甘油菌盒
- 甘油菌位置

普通用户不能查看。

库管员只能查看自己负责类型。

超级管理员可以查看全部。

------

# 十二、审核状态

系统必须设置独立审核状态：

```text
草稿
待审核
审核通过
审核驳回
停用
```

审核状态不负责表达库存状态。

------

# 十三、质粒审核

## 13.1 提交审核

用户提交：

```text
草稿
↓
待审核
```

系统记录：

- 提交人
- 提交时间

------

## 13.2 审核人

审核人必须为：

- 当前质粒类型对应的库管员
- 或超级管理员

普通用户不能审核。

------

## 13.3 审核通过

审核通过后：

```text
待审核
↓
审核通过
```

正式进入质粒档案。

------

## 13.4 审核驳回

审核驳回必须填写审核意见。

流程：

```text
待审核
↓
审核驳回
↓
用户修改
↓
重新提交
↓
待审核
```

------

# 十四、库管员需求

库管员拥有普通用户全部能力。

此外：

## 14.1 质粒审核

只能审核自己负责类型。

------

## 14.2 质粒维护

可以修改自己负责类型的质粒管理信息。

------

## 14.3 库存管理

可以：

- 入库
- 出库
- 盘点
- 调整
- 查看库存
- 设置低库存阈值

------

## 14.4 借用审核

可以审核自己负责类型的借用申请。

审核时必须检查：

- 当前库存
- 申请数量
- 借用合理性
- 用户情况

并确定实际批准数量。

------

## 14.5 归还管理

可以：

- 设置归还规则
- 设置归还时间
- 审核归还
- 调整实际归还数量

------

## 14.6 违规管理

可以：

- 查看违规
- 创建违规记录
- 处理违规
- 警告
- 暂停借用权限
- 设置黑名单
- 移除黑名单

------

# 十五、超级管理员需求

超级管理员拥有全部功能。

可以：

- 管理所有质粒
- 管理所有质粒类型
- 管理所有库存
- 管理所有借用
- 管理所有归还
- 管理全部违规
- 管理黑名单
- 指定类型库管员
- 修改系统配置
- 管理角色
- 管理权限
- 查看审计信息

------

# 十六、质粒类型管理

超级管理员可以：

- 新增类型
- 修改类型
- 启用类型
- 停用类型
- 指定库管员
- 修改库管员

一个类型只能有一个有效库管员。

------

# 十七、库存管理需求

库存单位统一：

```text
μL
```

库存包括：

- 当前库存
- 低库存阈值
- 库存状态

库存状态：

```text
可用
低库存
耗尽
停用
```

------

# 十八、库存操作

库存支持：

### 入库

增加库存。

### 出库

减少库存。

### 借用

借用审核通过后自动产生库存扣减。

### 归还

归还审核通过后自动增加库存。

### 盘点调整

实际盘点与系统库存不一致时，由库管员进行调整。

### 报废/处置

需要减少库存，并记录原因。

------

# 十九、库存流水

所有库存变化必须产生库存流水。

流水必须记录：

- 质粒
- 操作类型
- 操作数量
- 操作前库存
- 操作后库存
- 操作人
- 操作时间
- 关联业务单据
- 操作原因
- 备注

禁止前端直接修改当前库存。

------

# 二十、低库存预警

库管员可以设置低库存阈值。

例如：

```text
库存 > 100 μL
→ 正常

库存 <= 100 μL
→ 低库存

库存 = 0
→ 耗尽
```

低库存时通知对应库管员。

------

# 二十一、借用申请

普通用户可以提交借用申请。

申请至少包含：

- 质粒
- 申请数量
- 借用原因

系统自动记录：

- 申请人
- 申请时间
- 当前状态

------

# 二十二、借用审核

借用申请提交后进入：

```text
待审核
```

由对应质粒类型库管员审核。

审核通过时：

- 确定实际借用数量
- 确定归还规则
- 确定归还时间
- 产生库存出库

审核拒绝时：

- 不产生库存变化
- 记录拒绝原因

------

# 二十三、申请数量与实际数量

必须分别保存：

```text
申请数量
实际批准数量
```

例如：

```text
申请：500 μL
批准：300 μL
```

不能覆盖原申请数量。

------

# 二十四、归还类型

归还类型固定为五种：

```text
1. 质粒+甘油菌
2. 只归还质粒
3. 只归还甘油菌
4. 无须归还
5. 其他
```

选择：

```text
其他
```

时必须填写自定义说明。

------

# 二十五、归还

需要归还时，系统记录：

- 归还截止时间
- 归还类型
- 应归还数量
- 实际归还数量
- 归还要求
- 备注

------

# 二十六、逾期

系统按照归还截止时间判断：

```text
未到期
↓
到期提醒
↓
逾期
↓
违规
```

可以向用户发送提醒。

------

# 二十七、违规

违规业务用于处理：

- 逾期未还
- 未按要求归还
- 其他借用违规

具体违规类型允许后续扩展。

违规记录必须保存：

- 用户
- 借用记录
- 违规类型
- 违规时间
- 违规说明
- 处理结果
- 处理人
- 处理时间

------

# 二十八、黑名单

黑名单用于限制存在严重或持续违规行为的用户。

支持：

- 加入黑名单
- 查看黑名单
- 移除黑名单

必须记录：

- 用户
- 加入原因
- 加入时间
- 操作人
- 移除时间
- 移除人
- 移除原因

------

# 二十九、用户借用权限

普通用户可以申请借用。

但如果用户处于有效黑名单：

> 系统不得允许其正常提交借用申请。

后端必须进行校验。

不能只依靠前端按钮隐藏。

------

# 三十三、业务状态总览

## 质粒审核

```text
草稿
 ↓
待审核
 ├── 审核通过
 │      ↓
 │    正式档案
 │
 └── 审核驳回
        ↓
      修改
        ↓
      再提交
```

## 借用

```text
申请
 ↓
待审核
 ├── 驳回
 │
 └── 通过
      ↓
   确定实际数量
      ↓
   库存出库
      ↓
   使用
      ↓
   归还/无需归还
```

## 归还

```text
待归还
 ↓
到期提醒
 ↓
归还申请
 ↓
审核
 ├── 通过 → 库存回库
 └── 驳回 → 按业务处理
```

# 三十四、非功能需求

## 34.1 数据一致性

库存相关操作必须保证事务一致性。

例如借用审核通过时：

```text
借用状态更新
+
库存扣减
+
库存流水生成
```

必须作为一个业务事务处理。

------

## 34.2 权限安全

后端必须进行权限校验。

不能仅依赖前端隐藏按钮。

------

## 34.3 数据追溯

关键业务必须可以追溯：

```text
谁
在什么时间
对哪个对象
执行了什么操作
操作前是什么
操作后是什么
```

------

## 34.4 文件安全

上传文件必须使用系统已有文件管理能力。

不得自行实现一套独立文件存储机制。

------

# 三十五、明确不做的内容

V2.0不包含：

- 使用反馈
- 独立审核员角色
- 一个类型多个库管员
- 普通用户查看存放位置
- 普通用户查看库存数量
- 普通用户查看甘油菌数量
- 普通用户查看甘油菌规格
- 用单一 `status` 同时表示审核和库存状态
- 用 `lab_plasmid.volume` 作为唯一动态库存账本

------

# 三十六、需求验收标准

V2.0质粒管理模块至少满足：

### 质粒

-  可以新建质粒
-  可以保存草稿
-  可以修改草稿
-  可以删除草稿
-  可以提交审核
-  可以审核
-  可以驳回
-  可以重新提交

### 类型

-  可以管理质粒类型
-  每个类型只能有一个库管员
-  库管员只能管理负责类型

### 库存

-  可以入库
-  可以出库
-  可以借用扣减
-  可以归还增加
-  可以盘点
-  可以调整
-  可以产生库存流水
-  可以低库存预警

### 借用

-  用户可以申请
-  库管员可以审核
-  可以设置实际借用数量
-  可以设置归还规则

### 归还

-  支持五种归还类型
-  支持归还申请
-  支持归还审核
-  支持逾期

### 违规

-  可以产生违规记录
-  可以处理违规
-  可以加入黑名单
-  可以解除黑名单

### 权限

-  普通用户不能看到敏感信息
-  库管员只能管理负责类型
-  超级管理员可以管理全部

### 审计

-  关键操作有记录
-  库存变化有流水
-  审核有历史
