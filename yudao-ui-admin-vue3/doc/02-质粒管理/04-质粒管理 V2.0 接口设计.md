# 质粒管理 V2.0 接口设计

## 1. 文档目的

本文档用于定义“本草基因组学管理平台——质粒管理 V2.0”的后端 REST API。

本文档承接：

- `01-质粒管理V2.0需求.md`
- `02-质粒管理V2.0数据库设计.md`
- `03-质粒管理V2.0权限设计.md`

接口设计必须遵循以上三个文档。

本接口设计的目标是：

```text
需求
 ↓
数据库
 ↓
权限
 ↓
接口
 ↓
后端实现
 ↓
前端调用
```

任何接口实现不得脱离上述设计自行增加业务规则。

------

# 2. 接口设计原则

## 2.1 使用项目现有 API 风格

接口路径、HTTP 方法、统一响应结构、异常处理、分页参数等，优先遵循当前 RuoYi-Vue-Pro 项目已有规范。

不要为了质粒管理重新设计一套 API 基础框架。

------

# 6. 新增质粒类型

```http
POST /lab/plasmid-type/create
```

权限：

```text
lab:plasmid:type:create
```

仅超级管理员。

请求：

```json
{
  "code": "FUNCTION",
  "name": "功能质粒库",
  "managerId": 10001,
  "sort": 10,
  "status": 1,
  "remark": ""
}
```

后端校验：

1. code 不为空
2. name 不为空
3. code 唯一
4. managerId 必须对应有效用户
5. 一个类型只能设置一个有效库管员
6. 库管员必须具备相应系统角色
7. 禁止重复创建相同类型


```text

```

请求：

```json
{
  "id": 1,
  "managerId": 10001
}
```

业务规则：

```text

        ↓
```


# 37. 库存状态计算

系统统一使用：

```text
可用
低库存
耗尽
停用
```

计算逻辑：

```text
currentQuantity = 0
    → 耗尽

currentQuantity > 0
AND currentQuantity <= lowStockThreshold
    → 低库存

currentQuantity > lowStockThreshold
    → 可用

质粒停用
    → 停用
```

库存状态与：

```text
auditStatus
```

完全分离。

# 45. 借用审核规则

库管员审核时：

```text
申请数量
↓
库存检查
↓
实际批准数量
↓
设置归还规则
↓
生成出库
```

库管员可以：

```text
申请50μL
实际批准30μL
```

不能批准：

```text
approvedQuantity <= 0
```

也不能：

```text
approvedQuantity > 当前库存
```

------

# 46. 借用审核通过事务

审核通过必须在同一个事务中完成：

```text
借用状态更新
        ↓
库存锁定
        ↓
库存扣减
        ↓
生成出库流水
        ↓
记录借用实际数量
        ↓
更新库存状态
```

任何一步失败：

```text
整体回滚
```

防止：

```text
借用已通过
但库存没有扣减
```

或者：

```text
库存扣减
但借用没有通过
```

# 65. 并发控制

库存操作必须考虑并发。

典型场景：

```text
库存100μL

用户A申请80μL
用户B申请50μL
```

不能出现：

```text
A审核通过 → 80
B审核通过 → 50
最终库存 = -30
```

因此库存扣减必须：

```text
事务
+
数据库行锁/条件更新
```

确保库存不会变成负数。

# 66. 库存条件更新建议

可以采用：

```sql
UPDATE lab_plasmid_inventory
SET current_quantity = current_quantity - #{quantity}
WHERE plasmid_id = #{plasmidId}
  AND current_quantity >= #{quantity};
```

然后检查：

```text
affectedRows == 1
```

如果：

```text
affectedRows == 0
```

则认为库存不足并回滚业务。

具体实现应遵循项目现有 DAO/Mapper 风格。

# 82. V2.0 接口设计最终约束

本接口文档确定以下规则：

1. 不允许普通用户直接修改正式质粒。
2. 不允许普通用户访问库存接口。
3. 不允许普通用户访问存储位置。
4. 不允许普通用户查看质粒体积、甘油菌规格及数量。
5. 不允许库管员管理其他类型质粒。
6. 不允许库管员审核其他类型质粒。
7. 一个质粒类型只能有一个库管员。
8. 库管员同时承担该类型审核职责。
9. 审核状态和库存状态必须分离。
10. 库存必须使用独立库存表管理。
11. 库存变化必须产生库存流水。
12. 借用审核通过与库存扣减必须处于同一事务。
13. 归还审核通过与库存增加必须处于同一事务。
14. 库存不得出现负数。
15. 所有敏感字段必须由后端控制返回。
16. 文件下载必须进行业务权限校验。
17. 普通用户只能导出自己的借用/归还记录。
18. 库管员只能导出自己负责类型的数据。
19. 超级管理员可以访问全部数据。
20. 不得通过前端隐藏按钮代替后端权限控制。
21. 不得让 AI 编码工具自行改变上述业务规则。
22. 实际接口路径、权限注解、VO 命名等细节必须优先遵循现有 RuoYi-Vue-Pro 项目代码规范。
